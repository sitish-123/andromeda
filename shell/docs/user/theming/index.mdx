Controls the dark/light modes used by Noctalia and by your apps.

```toml
[theme]
mode              = "light"       # dark | light | auto; another client changing the system scheme is adopted
shell_mode        = "follow"      # follow | dark | light | auto
pure_black_dark   = false         # replace dark-mode backgrounds with pure black
sync_color_scheme = true          # sync the GNOME color-scheme preference with mode
toolkit_themes    = true          # GTK, Qt, KDE and fcitx5 apps use the desktop colors and accent
```

Theme changes apply live when the resolved config changes, whether through Settings or edits to `~/.config/noctalia/*.toml`. See [Palette](/noctalia/theming/palette/) for color roles.

---

## `mode`

`dark` or `light` selects the palette variant directly. `auto` switches between them using the shared sunrise/sunset schedule in [`[location]`](/noctalia/services/location/) (same rules as [Night Light](/noctalia/services/night-light/)): sunrise and sunset computed from your coordinates, or your own `sunset` / `sunrise` times when [`custom_schedule = true`](/noctalia/services/location/#custom-schedule). Night light does not need to be enabled for theme auto to follow the schedule. When the schedule cannot be resolved, `auto` uses the light (day) palette until a valid schedule is available.

This is the mode your apps run in: it selects the GTK, Qt and KDE colors (when `toolkit_themes` is on), the GNOME `color-scheme` preference (when [`sync_color_scheme`](#sync_color_scheme) is on), and the mode reported to [`theme_mode_changed`](/noctalia/automation/hooks/) hooks. `theme-mode-toggle`, `theme-mode-set`, the control center shortcut, and the theme mode bar widget all act on this key.

## `shell_mode`

Noctalia's own mode: bars, panels, the launcher, wallpaper directory selection, and the greeter appearance.

| Value            | Description                                                            |
| ---------------- | ---------------------------------------------------------------------- |
| `follow`         | Track `mode`, so Noctalia and your apps switch together (default).     |
| `dark` / `light` | Pin Noctalia to that variant while `mode` keeps driving apps.          |
| `auto`           | Switch Noctalia on the `[location]` schedule, independently of `mode`. |

Pinning it gives combinations such as a permanently dark bar with light apps, or a dark bar while apps follow the day/night schedule. Toolkit colors and the GNOME `color-scheme` preference never follow `shell_mode`; a `shell_mode`-only change repaints only Noctalia.

## `pure_black_dark`

When `true`, replaces dark-mode background roles with pure black while preserving the palette's foreground and accent colors. It has no effect in light mode. Accessibility `high_contrast` also forces this behavior for dark themes.

## `sync_color_scheme`

When `true` (default), Noctalia writes `org.gnome.desktop.interface color-scheme` (`prefer-dark` or `prefer-light`, through `gsettings` or `dconf`) whenever `mode` changes. Browsers, Electron, Qt, and GTK apps read this preference through the desktop portal to pick their dark or light look. Set it to `false` to manage the preference yourself, for example to keep light apps under a dark `mode`.
